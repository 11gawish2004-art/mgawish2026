## نظرة عامة

طلب كبير يحتوي على 8 ميزات منفصلة. سأقسّمها إلى مراحل قابلة للتنفيذ مع توضيح ما هو ممكن وما يحتاج توضيحًا.

---

## المرحلة 1: تحسينات قسم حالات الزواج

في `MarriageCasesScreen.tsx` عند إضافة حالة جديدة:
- إضافة حقل **تاريخ تقديم الطلب** (`requestDate`)
- إضافة حقل **تاريخ تقديم المساعدة** (`aidDate`)
- إضافة حقل **كود الحالة** (يُولَّد تلقائيًا، مثل `MAR-2026-0001`)
- إضافة حقل **نوع المساعدة** (مادية / عينية)
- إضافة حقل **هل تم تقديم المساعدة؟** (نعم/لا)
- في طباعة الكشف: إظهار الكود، حالة التقديم، ونوع المساعدة

## المرحلة 2: قسم التوزيعات (جديد)

إنشاء `DistributionsScreen.tsx`:
- قائمة بكشوف التوزيع المحفوظة (كل كشف منفصل)
- زر "إنشاء كشف جديد" يفتح حوار اختيار الحالات
- في الحوار: عرض **جميع الحالات** من (cases / marriageCases / seasonalCases / reception) مع اسم القسم المصدر
- بحث + اختيار متعدد (checkboxes)
- لكل حالة في الكشف: نوع المساعدة المقدمة، تم الاستلام؟، تاريخ التوزيع
- طباعة الكشف بهذه الأعمدة
- تخزين في Supabase: جدولان `distribution_lists` و `distribution_list_items`

## المرحلة 3: تقييم بالذكاء الاصطناعي

في أقسام (الحالات / الحالات الموسمية / الاستقبال):
- زر "تقييم بالذكاء الاصطناعي" داخل بطاقة/تفاصيل الحالة
- يستدعي Lovable AI (`google/gemini-3-flash-preview`) عبر server function
- يحلل البيانات المدخلة + أسماء الملفات المرفقة (لا يحلل محتوى الصور حاليًا إلا لو طلبت ذلك)
- يُرجع: نتيجة (مستحق / غير مستحق / يحتاج مراجعة) + سبب + درجة %
- المستخدم يستطيع تعديل النتيجة يدويًا وحفظها مع الحالة

## المرحلة 4: المساعد الصوتي

- زر عائم (FAB) في **يمين** الشاشة (بدلًا من اليسار)
- ضغط مستمر للتسجيل → إرسال الصوت لـ Lovable AI (transcription + chat)
- الردّ يظهر نصًا + يُقرأ صوتيًا (TTS عبر Web Speech API للمتصفح)
- يجاوب عن أسئلة عن استخدام البرنامج وبيانات الحالات

## المرحلة 5: قسم المبرمج — الشعار والأيقونة

في `DeveloperScreen.tsx`:
- رفع صورة الشعار → تُحفظ في Supabase Storage (bucket `images/branding/logo.png`)
- رفع أيقونة التطبيق → `images/branding/icon.png`
- جدول `app_settings` يخزن المسارات
- مكوّن `Logo.tsx` الموجود يقرأ الشعار من هذا الإعداد (مع fallback)
- ملاحظة: تغيير أيقونة المتصفح/PWA يحتاج تحديث `manifest.json` + favicon ديناميكيًا — سأطبّقها عبر إدراج `<link rel="icon">` ديناميكي

## المرحلة 6: كشف القبض الشهري (جديد)

إنشاء `MonthlyPayrollScreen.tsx`:
- جدول حالات بالبيانات: الاسم، الرقم القومي، التليفون، الحالة الاجتماعية، المبلغ
- أزرار: استيراد Excel، تصدير Excel، فلترة، ترتيب بعمود واحد أو عمودين
- عند استيراد Excel: حوار يسأل عن mapping كل عمود
- طباعة الكشف بترويسة كاملة:
  - **يمين الترويسة**: مديرية الشؤون الاجتماعية بالدقهلية / إدارة بنبروه / جمعية بصمة خير / مشهرة 2510-2015
  - **يسار الترويسة**: شعار الجمعية
  - **منتصف**: العنوان "كشف بأسماء الحالات المستحقة للمساعدة بالجمعية عبارة عن كفالة شهرية بقيمة 100 جنيه لكل أسرة بتاريخ __/__/20__"
  - الجدول: م - الاسم - الرقم القومي - التليفون - الحالة الاجتماعية - المبلغ - التوقيع
  - **مكرر في كل صفحة**: الإجمالي السابق (أعلى) + إجمالي الصفحة (أسفل) + لجنة التوزيع (3 أعضاء بأسمائهم وخانات توقيع)
- جدول Supabase: `monthly_payroll_lists` + `monthly_payroll_items`

## ملاحظات تقنية

- **التخزين**: استخدام Supabase tables بدل Firebase للميزات الجديدة (التوزيعات، كشف القبض، إعدادات العلامة التجارية، تقييمات الذكاء الاصطناعي)
- **الذكاء الاصطناعي**: Lovable AI Gateway مع `google/gemini-3-flash-preview` (افتراضي)
- **المساعد الصوتي**: Web Speech API للـ TTS وتسجيل صوتي → AI للنص
- **استيراد/تصدير Excel**: مكتبة `xlsx` (SheetJS)
- **الطباعة**: CSS print + كرر header/footer لكل صفحة عبر `position: running()` أو نهج تقسيم يدوي

## ما يحتاج تأكيدك

1. **حجم العمل ضخم جدًا** (8 ميزات كبيرة، عشرات الملفات، عدة جداول قاعدة بيانات). هل تريد تنفيذ **الكل دفعة واحدة** أم **مرحلة مرحلة** (موصى به)؟
2. **التقييم بالذكاء الاصطناعي**: هل تريده يحلل **محتوى الصور المرفقة** فعلًا (أبطأ وأغلى) أم النص فقط + أسماء الملفات؟
3. **كشف القبض الشهري**: المبلغ ثابت 100 جنيه لكل حالة أم متغير لكل حالة (الطلب يتناقض قليلًا — يقول "المبلغ" كحقل و"100 جنيه" كنص ثابت في العنوان)؟

أقترح البدء بـ **المرحلة 1 + 2 + 5** (الزواج + التوزيعات + الشعار) كدفعة أولى، ثم الباقي بعد المراجعة. وافق على الخطة وحدد ترتيب الأولويات وسأبدأ التنفيذ.
